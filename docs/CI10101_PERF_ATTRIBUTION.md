### ② MP2（不开抽屉，静置 30s）

### ④ 预取 delta（force-stop 清内存 + rm 磁盘 → 0 → 开抽屉 10s 不滚动）
- 清理后磁盘=0；重启后开抽屉前磁盘=0。
- 开抽屉停留 **10s** 后：磁盘 **+13 个**；该窗口 CPU avg **297%**（12.2s 窗口）。
- 随后进入设置读用量：`内存 56 条 · 磁盘 56 个 / 130 KB`（后续动作继续补齐 → 总数增长）。
- 判定：**单次打开首批 13 个 ≈ 限流上限（≤16 立即）生效**；但开抽屉瞬时 CPU 峰 ~297%（预取决算/网络）。

## 6. 结论（CPU 主因拆解）
- **MP2 软音频不是主因**：MP2 不开抽屉 62.0% < AAC 82.3%；软解反而更低。
- **主因是“基础播放 + 后台/UI”约 62–82%**：含 AVC 硬解、EPG/网络后台、Compose UI 等整进程开销；开抽屉浏览（③）不额外显著增加（62.1%）。
- **开抽屉瞬间预取决算/网络有 ~297% 瞬时峰**（④），但预取限流已把首批压到 13 个（≤16），非 57–120 突发。
- **jank 明显偏高且真实**（中位 54.55%、90th 113），需 framestats/Perfetto 定位（优先怀疑预取决算/EPG 刷新/布局）。
- 建议后续：per-thread `/proc/<pid>/task/*/stat` 或 Perfetto 把 62–82% 拆到 video/audio/EPG/网络；开抽屉峰值用 trace 确认预取决算占比；冷首图在确认 drawer 打开下重测。
- 未改代码、未改原包数据；设备保持 CI10101。
