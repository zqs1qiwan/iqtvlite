# 睛彩系列播不了：源侧与码流分析（2026-11-21）

## 1. 源可达性（从 PC 直接探测）

播放列表 `https://iptv.laobaitv.net/?m3u=true` 中睛彩三条：

| 频道 | tvg-id | URL |
|---|---|---|
| 睛彩竞技 | 睛彩竞技 | `http://192.168.2.1:4022/rtp/239.3.1.125:8001` |
| 睛彩篮球 | 睛彩篮球 | `http://192.168.2.1:4022/udp/239.3.1.126:8001` |
| 睛彩青少 | 睛彩青少 | `http://192.168.2.1:4022/rtp/239.3.1.127:8001` |

PC 上用 `curl --max-time 6` 实测三条全部 **HTTP 200、约 1.04 MB/s（≈8.3 Mbps）、6 秒收到 6.25 MB** → **源与组播代理均正常，非“源不可达”**。

## 2. 码流结构（PC 下载 8.4MB / 约 7 秒样本分析）

`local/diag/jingcai_125.ts`，44800 个 188 字节 TS 包：

- PAT → PMT PID 103；PCR PID 104
- 视频：PID 101，`stream_type=0x1B`（**H.264/AVC**）
- 音频：PID 102，`stream_type=0x03`（**MPEG-1 audio / Layer II**）
- 视频 NAL 统计：IDR(type 5) **17** 次、SPS(7) 17、PPS(8) 17、非 IDR 切片(1) 180 → **关键帧/SPS/PPS 齐全，码流可解码**
- `cc_errors` 仅出现在 PID 8191（null 包，无连续性语义），非真实丢包

结论：**睛彩是标准 H.264 + MP2 的 TS 流，且约 7 秒内出现 17 次 IDR；App 侧（平台硬解 AVC + FFmpeg 解 MP2）在能力上应能播放。**

## 3. 真机侧历史现象（CI10127 及之前）

- 三台均成功初始化解码器（avc 1920×1080 + MP2），但长时间 `state=2`、无 `first_frame`、无 `audio_advancing`、无崩溃。
- 常见可能：该路 8.3 Mbps 高码率在测试盒 Wi-Fi 路径下起播填充慢 / ExoPlayer 首包/丢包策略 / 代理对该 path 的响应差异 / 早期版本无 MP2 扩展导致音频轨失败拖住起播。

## 4. 待办（设备恢复后）

1. 用当前版本（CI10132）逐台重测 117/118/119，抓 `IQTV-METRICS`（state/rebuffers/first_frame/audio_format/decoder）与 `IQTV-ZAP` 分段；
2. 对照普通 CCTV（同代理、低码率）与睛彩（8.3Mbps）差异，判断是否带宽/首秒吞吐；
3. 若仍卡缓冲，可临时提高该场景起播缓冲或关闭 MP2 扩展做对照（单变量）。

## 5. 结论口径

- **不能说“源不可达”**：PC 实测源正常、码流标准。
- **不能说“App 解码不支持”**：AVC 硬解 + MP2 扩展均具备，码流含 IDR/SPS/PPS。
- 当前应表述为：**“睛彩在测试盒上起播失败/卡缓冲，根因待设备复测定位（源与码流均正常）”**。
