→ **残影仍然存在，但是"间歇性"的**：本轮 5 轮扫描中**仅在 61–72 区间命中 2/2 次**（`北`/`北`），其余 4 轮全部干净；随后专门补测落到 64–75 区间时又 2/2 干净。
即：**不是 100% 稳定复现，而是"特定行 + 特定落点"的偶发**（`60. 卡酷少儿`/`61. 北京IPTV` 附近最易见）。
t58 的 `key("sub_$index")` + `softWrap=false` + `clipToBounds` 四手段**显著降低了出现频率，但未根除**。
**新线索**：命中时两次 dump 都出现同一个字（`北`），且**只画 1 个字**，更像**该行副标题在 16dp 高度 Box + `softWrap=false` 下被测量成极窄可用宽度**（"北京…" 只画 "北"），而不是绘制残留。建议下一轮直接查该行：①副标题文本是否含全角空格/不可见字符 ②`softWrap=false` + Ellipsis 在窄宽下的测量结果 ③打 `onTextLayout` 的 `lineCount`/`didOverflowWidth`/`size.width`。

## 6. 建议

1. **接受 Draw 收益、停止调参**：三层 RenderNode 把 Draw 从 10.6 拉回 5.0/5.7，**这段代码值得保留**（回退只需删三处 `graphicsLayer()`）。
2. **50th 不再由 Draw 决定**：UI 中位 24–29.6ms + 巨帧 1–3 波动，说明瓶颈在 **Compose 组合/测量 + 弱机 CPU 抖动**。要冲 50th≤45 只有两条路：
   - 换渲染方案（自绘虚拟列表 / 预渲染行位图）——**建议单独立项**；
   - 或把「开抽屉」从"补 28 行"降到"只补可视 12 行 + 滚动再补"（但 t50 已证 openWindow 18 会反噬），收益不确定。
3. **残影仍在 61–72 区间稳定复现**，建议按 §3 的三条新线索定位（优先查该行的文本内容与 Ellipsis 测量），不要再堆 clip/key 手段。
4. **判定口径建议**：本轮三项指标中 50th 无法在 Compose 方案下达标，建议把验收线改为「Draw ≤6 且 巨帧 ≤3 且 50th ≤60」，或直接冻结当前实现并在文档写明「50th 53–57ms 为 Compose 方案上限」。
