# Android TV IPTV 播放器 PRD

## 1. 产品概述

一款面向 Android TV、完全通过遥控器操作的 IPTV 播放器。采用 tivimini 的 UI/UX 作为直接基础，再针对老白的 IPTV 场景做二次改进。播放列表与 EPG 解析、频道切换、视频播放要适配目标 TR100-G9 设备及内网流。

## 2. 当前用户需求

1. **台标**：正确显示频道 logo；透明 PNG 原样呈现，不加额外边框或卡片；换台信息中也要有台标。
2. **分开设置与节目单**：日常就是换台；节目单单独呼出，设置单独呼出。设置/节目单从屏幕一侧展开并带透明度，尽量不遮挡节目。
3. **交互基线**：直接移植 tivimini UI/UX，并吸收 TiviMate 的层级式交互；不要重新回到 iqtvlite 旧版三栏 UI。
4. **换台信息**：频道名、台标、正在播放、接下来播放。
5. **IPTV 基础设置**：可配置遥控器按键（换台、上一台等）、数字键输入频道号（例：`112`）、启动恢复上次频道、播放列表与 EPG 刷新时机、节目列表点击行为。
6. **品牌**：统一重做视觉元素、图标和品牌资产，质量对标 Apple TV 的精致度；视觉系统内部一致。
7. **扫码推源**：保留 tivimini 手机扫码/局域网推送配置功能。

## 3. 测试配置

- 直播源预填：`https://iptv.laobaitv.net`
- EPG 预填：`https://epg.laobaitv.net`
- 以上仅是测试用默认值，不能移除二维码、手机推送，也不能限制其他源。
- M3U 包含 156 条 `#EXTINF`（2026-11-18 实测）；条目/去重后的频道编号映射要明确。
- 直播 URL 使用内网地址，例如 `http://192.168.2.1:4022/rtp/...`。

## 4. 交互与视觉验收

- [ ] 首次源配置页面同时显示二维码、局域网推送地址和两个预填源地址；遥控器可到达并启动播放。
- [ ] 扫码推送能覆盖/更新测试源并开始播放。
- [ ] 全屏播放时数字键可以连续缓冲输入；输入 `112` 显示完整数字，等待后切到第 112 号台；无效号码有明确提示。
- [ ] 数字频道定义（原始 M3U 序号或合并后分组序号）固定，并与 UI 显示一致。
- [ ] 默认换台、上一台、节目单、设置的按键职责可以配置且互不冲突。
- [ ] 启动时恢复上次播放的频道。
- [ ] 节目单和设置独立呼出；侧栏从屏幕一侧展开，宽度不超过屏幕约 1/3，保留视频可见。
- [ ] 频道列表和换台信息展示透明台标、频道名、正在播放和接下来播放。
- [ ] 节目列表点击行为、EPG/播放列表刷新策略可配置。
- [ ] 品牌颜色、焦点态、图标、banner、频道卡片遵循统一设计系统；不覆盖 logo 原始透明边缘。

## 5. 网络与播放兼容

- M3U 请求需跟随 HTTP 重定向；不可把某次观测到的状态写死为永久行为。2026-11-18 实测 `https://iptv.laobaitv.net` 为 HTTP 200、`application/x-mpegURL`、无重定向。
- 支持频道级 M3U 属性 `http-user-agent`。`VLC` 映射到 `VLC/3.0.20 LibVLC/3.0.20`，并确保该 UA 到达实际 Media3 HTTP 请求；其他明确 UA 原样保留。
- 目标设备的 IPv6 出口可能不可用；播放列表、EPG、流媒体访问验证 IPv4 优先 DNS。
- EPG 可能是没有 `Content-Encoding` 头的裸 gzip；通过头部 magic `1f 8b` 判断并解压，再解析 XMLTV。
- 区分源站流错误与 app 播放错误。2026-11-18 实测：M3U 中 112 号“财富天下”流返回 HTTP 503（VLC/TiviMate UA 均相同）；CCTV-1 流返回 HTTP 200 并持续输出数据。

## 6. 建议实施顺序

1. 以 tivimini 原始界面为基线，先让源配置、扫码、播放、抽屉和遥控器操作稳定。
2. 修复并验证数字跳台、频道级 UA、IPv4、EPG gzip、刷新/缓存等数据路径。
3. 按“换台信息 → 频道/节目单抽屉 → 分组层级 → 独立设置”的顺序改交互。
4. 最后统一品牌资产与全局焦点/色彩系统。
5. 每个切片先构建、单测，再在目标盒子验证；端到端播放、遥控交互和 CI 全通过后才 Release。
